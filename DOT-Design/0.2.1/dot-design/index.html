DOT-Design

DOT-Design defines the portable model and reference tooling used to describe, validate, deploy, and compose Dynamic Open Trust (DOT) components in the MARE 6G security ecosystem.

A DOT packages four concerns without collapsing them into one runtime-specific description:

  • capability — Skills describe what the component does;

  • contract — OpenAPI, AsyncAPI, Protobuf, or GraphQL documents describe authoritative interactions;

  • composition — Anchors give selected Contract operations stable identities and PROVIDES or REQUIRES roles; and

  • deployment — Runtimes and deployment manifests describe where and how the component can run.

dot.json is the deployable DOT definition and the only source inspected by dotx deploy. Connections between deployed DOT instances are described in a separate composition document. Concrete addresses, credentials, and live policy results never become Anchor fields.

Supported Contract standards

Standard Anchor selector

OpenAPI

RFC 6901 URI-fragment JSON Pointer to an Operation Object

AsyncAPI

RFC 6901 URI-fragment JSON Pointer to an Operation Object

Protobuf

Fully qualified service method

GraphQL

Root-field schema coordinate

Contractless Anchors remain available for interactions that cannot be described by one of these standards. They must declare direction, protocol, and media type explicitly.

Maturity and scope

The DOT-owned Anchor model, service-port binding, generated schema, repository resolution, conformance fixtures, dot.mare6g.eu/v1 composition document, and dotx compose executor form the stable 0.2.1 Composition v1 profile.

The reference executor is intentionally fail-closed. It does not claim to be a general multi-host orchestrator, trust-policy engine, active security scanner, or replacement for Kubernetes, Helm, Docker, Vagrant, or an SFC implementation. See the supported composition profile for the exact boundary.

First steps

# Domain unit tests; no MongoDB required
mvn -pl DOT-Domain test

# Install the pinned CLI checkout on PATH
task cli:install

# Validate and inspect the canonical composition example
dotx compose validate DOT-Testing/e2e/api-gateway-oidc/scenario.yaml
dotx compose plan DOT-Testing/e2e/api-gateway-oidc/scenario.yaml

# Run the complete Anchor/composition repository gate
task testing:conformance
