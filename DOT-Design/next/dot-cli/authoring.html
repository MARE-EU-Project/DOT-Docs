Author an interface-aware DOT

Start by reusing a complete catalogue DOT. Author a new definition only for a genuinely new component or a local exercise; do not publish another root for an existing product. Add deployment alternatives to its canonical bundle instead.

These commands require the selected release CLI v0.3.0 or its matching source build, jq, catalogue access and network access to the pinned raw Contract. The released flow below covers owned OpenAPI interfaces; the four-standard guided editor described later requires current 0.4.0 source. Current-source authoring summaries name the saved file, distinguish declaration validation from live acceptance, and confirm unchanged runtime state. Follow-up commands use the actual quoted path; validation retains repository/offline selection while inspect reads the local definition without those flags. Follow the compatible-artifact installation routes. No Java, Jsonnet, Docker daemon or Kubernetes cluster is needed for the commands below; the last command renders a deployment without starting it.

Confirm the actual component release

--version is required for noninteractive authoring. Interactive mode asks for the actual tool release without inventing 0.0.0. Image packaging tags and Helm chart versions are not reliable substitutes: confirm the tool release yourself. Explicit source/test versions remain available for unreleased components.

Declare at least one meaningful --skill; repeat it for multiple capabilities. Use an existing catalogue capability where appropriate and document a genuinely new capability in Skills/. Creation does not infer Skills from an image.

Rehearse with the existing Prometheus Contract

This temporary exercise reuses Prometheus’s existing authoritative declaration; it creates no second catalogue entry and copies no dependency interface. From DOT-Design, prepare an empty exercise directory:

# Run from DOT-Design; set DOT_REPOSITORY=$PWD from a standalone catalogue.
DOT_REPOSITORY="${DOT_REPOSITORY:-$PWD/DOT-Repository}"
AUTHORING_DIR="$(mktemp -d -t dotx-authoring.XXXXXXXX)"
jq '.contracts[0]' "$DOT_REPOSITORY/DOTs/external/Prometheus-DOT/dot.json" \
  >"$AUTHORING_DIR/contract.json"

contract.json is one complete Contract in the generated DOT-Domain model, not a raw OpenAPI document or catalogue wrapper. It contains the owned ID, name, standard version, standard, format and HTTPS payload.url/sha256. For your own tool, provide its own declaration with a release-matched official specification where available. Never relabel another component’s Contract.

dotx new --from docker-image prom/prometheus:v3.15.1 \
  --name Prometheus --version 3.15.1 --skill Metrics-Scraping \
  --service prometheus --port http:9090 \
  --contract "$AUTHORING_DIR/contract.json" \
  --operation 'build-information=#/paths/~1status~1buildinfo/get' --bind http \
  --output "$AUTHORING_DIR/bundle/dot.json"

Expected: an owned-interface verification message (Owned OpenAPI interface verified in v0.3.0; Owned interface verified in current source). The command validates the declaration against the generated schema, checks exact ownership, downloads and verifies the payload using the ordinary bounded HTTPS/SHA-256 verifier, and resolves the selected operation using the composition resolver. It writes the complete Contract, the explicit Anchor ID, its service Contract reference and the named-port binding into dot.json only after verification succeeds.

build-information is the stable DOT-local wire identity, not a generated UUID or a display-name alias. --operation <anchor-id>=<selector> uses that exact key for both the Anchor and its service binding; name initially has the same value but may subsequently change independently. Use kebab-case keys. The selector remains separate from the Contract ID. Repeat --operation for additional provided operations on the same declared TCP port. --bind requires an exact service port name and never guesses a listener.

For a menu of operations and port choices, use --interactive --contract "$AUTHORING_DIR/contract.json" with the same source/name/version/Skill/port arguments and a new output path. Without an imported Contract, interactive mode offers an optional declaration-file prompt; leave it empty for a runtime-only scaffold. Do not overwrite this exercise’s output unintentionally.

Validate, inspect and render

dotx validate "$AUTHORING_DIR/bundle" \
  --schema "$DOT_REPOSITORY/Schema/schema.json" --profile reusable
dotx inspect "$AUTHORING_DIR/bundle"
dotx deploy "$AUTHORING_DIR/bundle" --deployment docker-image --dry-run

Expected: the reusable profile passes, inspection shows one owned Contract and one provided Anchor, and dry-run renders the Docker command. This checks the declared interface and binding, not a running API. The flow does not establish that a URL is vendor-owned or that its release metadata is truthful; review provenance. For live acceptance, follow the source-qualified guided demo. The released quickstart uses its own pinned artifact set; do not replace only one component of a qualified pair with an unrelated binary or catalogue revision.

The published v0.3.0 guided interface profile covers owned OpenAPI provided operations only. AsyncAPI, GraphQL, Protobuf, external dependency references and provider-neutral requirements remain supported by the domain and composition commands, but require explicit authoring. No protocol metadata is duplicated from the Contract and no compatibility or live-readiness claim is inferred.

Import directly from the official raw URL

Alternatively, the same native authoring command can construct the generated Contract declaration from a raw HTTPS URL. Run this after the previous exercise so both temporary outputs can be inspected and cleaned up together:

# Alternative: supply the official raw URL without hand-writing contract.json.
# This exercise creates no second catalogue entry.
AUTHORING_SPEC_BASE=https://raw.githubusercontent.com/prometheus/prometheus/v3.15.1
dotx new --from docker-image prom/prometheus:v3.15.1 \
  --name Prometheus --version 3.15.1 --skill Metrics-Scraping \
  --service prometheus --port http:9090 \
  --contract-url "$AUTHORING_SPEC_BASE/web/api/v1/testdata/openapi_3.1_golden.yaml" \
  --contract-name HTTP --contract-version 3.1.0 --contract-format YAML \
  --operation 'build-information=#/paths/~1status~1buildinfo/get' --bind http \
  --output "$AUTHORING_DIR/url-bundle/dot.json"
dotx validate "$AUTHORING_DIR/url-bundle" \
  --schema "$DOT_REPOSITORY/Schema/schema.json" --profile reusable
jq '.contracts[0]' "$AUTHORING_DIR/url-bundle/dot.json"

Expected: the resulting ID is Prometheus@3.15.1::OpenAPI::HTTP, with the official URL and a 64-character lower-case SHA-256 in payload. No raw document is embedded. --contract-version 3.1.0 matches the document’s openapi: 3.1.0, not its info.version or the tool’s --version 3.15.1. The upstream document’s info.version: 0.0.1-undefined remains unchanged inside the pinned payload; it is not copied into DOT Contract metadata. A standard-version mismatch fails before publication. Do not infer versions from a filename or rewrite upstream bytes.

To require bytes already approved by your team, add --contract-sha256 <trusted-digest>. A mismatch fails without replacing output. Without that option, the command pins the bytes retrieved on first use: review the URL, upstream provenance, release match, license and resulting digest before committing. Computing a hash does not prove that the URL is vendor-owned or that its API matches a deployed producer.

The downloader reuses validation’s HTTPS, public-address, redirect, timeout, size and credential-scoping controls. Mutable GitHub branch URLs are refused; use an official release tag or full commit. Transport failures withhold URL and credential details. --contract and --contract-url are mutually exclusive. For a derived specification hosted on GitHub Gist, use the raw gist.githubusercontent.com URL containing the full 40-character revision and filename, without query parameters, plus a trusted digest. Secret Gists are readable without authentication by anyone with the URL; GitHub tokens are not sent to them. Preserve source/license provenance and do not label a derived projection vendor-official merely because it is hosted externally. The published v0.3.0 URL importer requires explicit --contract-name, --contract-version and --contract-format JSON|YAML; it does not guess a standard from the URL.

Interactive authoring accepts either a declaration filename or an HTTPS URL, asks for missing metadata and offers the same verified operation/port menus. The digest selected during that prompt must still match at publication.

Recover from errors and clean up

  • Missing release: supply --version; no output is created.

  • Ownership mismatch: use the actual originating product/release, or an external Anchor reference for a dependency. Do not rename a dependency into ownership.

  • Download or digest failure: check access, the official raw URL and expected bytes. Never change a hash solely to bypass a failure.

  • Invalid selector: choose an operation from the verified specification. Encode OpenAPI selectors as URI-fragment JSON Pointers, including ~1 for /.

  • Binding failure: declare --port http:9090 and use --bind http.

  • Existing output: choose a new path. --force permits replacement only after verification. Complete bytes are staged and published atomically; a concurrently created output is not overwritten without --force. Forced replacement preserves existing Unix file mode bits and does not follow a destination symlink into another file. Staging failures preserve the old file.

Non-overwriting publication requires hard-link support in the output filesystem; unsupported filesystems fail closed rather than falling back to truncation.

new creates a fresh definition; it is not an incremental editor or migration command. --force replaces the whole scaffold using the supplied Anchor IDs; it does not preserve interfaces omitted from the new command. For an existing integrated DOT, edit its definition while retaining stable Anchor identities and review affected composition locks instead of regenerating the scaffold.

# Only the files created by this exercise; unexpected extra files are retained.
rm -- "$AUTHORING_DIR/bundle/dot.json" "$AUTHORING_DIR/contract.json"
if [[ -d "$AUTHORING_DIR/url-bundle" ]]; then
  rm -- "$AUTHORING_DIR/url-bundle/dot.json"
  rmdir -- "$AUTHORING_DIR/url-bundle"
fi
rmdir -- "$AUTHORING_DIR/bundle" "$AUTHORING_DIR"

Only exercise files are removed. No containers, networks, volumes or cluster resources were created. Developers can run the same documented commands and ownership-negative control with task testing:authoring from DOT-Design.

Current-source guided authoring for 0.4.0

These additions require the matching source build; the published v0.3.0 binary does not contain them. The reviewed 0.3.0 portable models and schemas are not expanded. Record dotx version --verbose and the exact source/catalogue revisions.

dotx new --interactive now offers verified operations for all four standards:

Standard Raw format Supported selector/profile

OpenAPI

JSON or YAML

Operation JSON Pointer, including supported additional operations

AsyncAPI

JSON or YAML

Version-3 send/receive operation; explicit broker endpoint in the composition

Protobuf

PROTOBUF

Fully qualified service method in a standalone specification

GraphQL

GRAPHQL

Declared query, mutation or subscription root field

New, edit and composition authoring use the same native Huh forms for text, editable defaults, scrolling choices and confirmations. Enter accepts a prefilled value; Ctrl-U clears the field. Candidate publication offers Write draft / Cancel, defaulting to Cancel. EOF or an incomplete form cannot authorize publication. Defaults containing control characters use an explained escaped line fallback when a single-line form cannot preserve their bytes losslessly.

In single-choice menus, type initial letters to filter immediately: Pro finds Prometheus, Key finds Keycloak. Search is case-insensitive and also matches text within a choice. Use ↑/↓ to browse, Backspace to edit the query, Enter to select and Ctrl-C to cancel. No / prefix is needed. Checkbox menus use Space to toggle, / to filter and Esc to finish filtering before toggling.

Set DOTX_NO_TUI=1 or ACCESSIBLE=1 for non-redrawing line menus. They also apply when output is redirected or the terminal is small or TERM=dumb: numbered menus use /text, n/p and q; configuration checkboxes use comma-separated names, * for all and empty for none. Confirmation remains an explicit text prompt, with no as the default. The browser uses the ordinary composition parsers and operation resolver; it does not create another compatibility engine. An operation menu is not evidence that every transport or feature in the standard is executable. Imported Protobuf dependencies that cannot be resolved by the existing standalone/well-known-import profile fail with no draft publication.

For URL imports, choose the exact canonical --contract-standard, name and raw format. Current source derives an omitted standard version from the verified payload’s native marker and omits it for GraphQL SDL. Tool --version remains the actual component release. A supplied standard version must still match. Use --offline only with the trusted digest and already verified cached bytes; a cold or corrupt cache is not repaired or bypassed.

AsyncAPI operations materialize a send/receive participant, not a local broker listener. Do not pass --bind; choose the broker’s actual service/port when building the composition. Existing MQTT, NATS, Kafka and AMQP acceptance profiles remain authoritative; declarations do not provision brokers or prove delivery.

Improve an existing DOT safely

From the matching DOT-Repository checkout root:

mkdir -p drafts
dotx edit DOTs/external/Prometheus-DOT/dot.json --interactive \
  --output drafts/prometheus.candidate.json --repository . --offline

Choose Skills, add an owned Contract, update its URL, add/change an Anchor operation or rebind an owned Anchor to a named service/port. IDs are retained for existing Anchors; no unaffected ID is regenerated. Selecting an AsyncAPI send/receive operation derives the correct role. Runtime-only definitions can gain their first interface; incomplete interoperability cannot be saved as a reusable candidate.

Expected: a semantic change summary followed by explicit confirmation. The complete candidate is checked against the generated model and ordinary Contract, selector and per-deployment binding rules before writing private, complete bytes. The original, deployment manifests, configuration, unrelated fields, locks and runtime state stay untouched. The editor refuses an existing output, a symlinked output parent, a changed original or a second catalogue dot.json. Cancellation, EOF, verification and publication errors leave no partial candidate.

The completion summary prints commands for reviewing the diff, validating with the selected local catalogue and offline mode, and inspecting the candidate. dotx validate <candidate.json> --repository <local-catalogue> --offline also works outside the catalogue tree: it uses that checkout’s generated schema and exact external Contract origins. It neither downloads missing bytes nor repairs corrupt caches. dotx inspect <candidate.json> displays the declaration; it does not accept repository/offline flags or prove a live API response.

For dotx new, the summary uses a catalogue discovered from the working directory when available. Its --repo/--repository option identifies a Helm chart repository, not a DOT catalogue. If no catalogue is discoverable, offline revalidation needs an explicitly selected local schema or catalogue; the summary explains this rather than printing an unusable command.

Review the diff and validate the candidate. Draft creation is not promotion: explicitly decide whether to replace the canonical file, review dependent composition locks for the intended interface change and rehearse affected APIs. Do not publish a candidate as another product root. Delete only the candidate file when abandoning the exercise; no runtime cleanup is necessary.
