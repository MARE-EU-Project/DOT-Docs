Compositions and connections

How to read this reference explains full objects versus ID-only views, conditional fields and validation boundaries.

AnchorReference

Identify a logical Anchor on one composition member.

The Anchor ID belongs to the referenced DOT, while the instance name belongs to this composition. Neither field is an address, a service name or a Contract operation selector; the executor resolves those relationships from the selected definition.

Java authority | Generated JSON Schema

JSON field Value Base presence Meaning and constraints

instance

string

Required

Name of the composition member containing the Anchor. minimum length: 1.

anchorId

string

Required

Exact DOT-local Anchor key on that member. minimum length: 1; pattern restrictions (see schema); conditional constraints (see schema).

Relationships

  • From ExposedAnchor: containment via target; diagram multiplicity 1.

  • From Wire: containment via from; diagram multiplicity 1.

  • From Wire: containment via to; diagram multiplicity 1.

  • To DotInstance: ID/name reference via instance.

  • To Anchor: ID/name reference via anchorId.

Shape example from the reviewed Java compatibility corpus (not a runnable deployment)
{
  "instance": "metrics",
  "anchorId": "http-api"
}

CdiDeviceBinding

Assign an installed CDI device to a logical device requirement of a deployment.

Bind the declared requirement to a concrete device of the same CDI kind. This does not install a CDI specification, allocate hardware or authorize an arbitrary host device path; availability and supported adapter behavior remain deployment concerns.

JSON field Value Base presence Meaning and constraints

string

Required

Logical device-requirement name declared by the selected service configuration. minimum length: 1.

string

Required

Fully qualified CDI device identity chosen by the operator. maximum length: 381; pattern restrictions (see schema).

Relationships

  "device": "vendor.example/gpu=0"

Composition

Describe one reusable use case by selecting DOT instances and connecting their logical interfaces.

This is a separate aggregate, not a DOT containing other DOT definitions. Instance references must name declared members and explicit readiness dependencies must be acyclic; interface wires may form cycles. Catalogue resolution, reviewed locks, credentials, deployment ownership and live acceptance remain separate executor concerns.

Java authority | Generated JSON Schema

JSON field Value Base presence Meaning and constraints

apiVersion

string

Required

Identifies the portable composition input profile understood by the reader. exact value "dot.mare6g.eu/v1"; pattern restrictions (see schema).

kind

string

Required

Distinguishes a composition declaration from other document kinds. exact value "Composition"; pattern restrictions (see schema).

id

string

Required

Stable identity used to associate lifecycle ownership with this composition, independent of its display name. pattern restrictions (see schema).

name

string

Required

Human-readable name for the use case, not a replacement for its ownership identity. minimum length: 1.

version

string

Required

Version label for this use-case declaration; it is not the version of every participating tool. minimum length: 1.

dots

array of DotInstance

Required

Named instances selecting canonical DOT definitions and their deployments. minimum items: 1.

contracts

array of ContractInput

Conditional / optional

Explicit interface-document inputs resolved from authoritative owners, without transferring Contract ownership.

wires

array of Wire

Conditional / optional

Logical connections from provided Anchors to required Anchors.

exposedAnchors

array of ExposedAnchor

Conditional / optional

Names for selected member Anchors at the composition boundary; these do not themselves publish a network listener.

Relationships

  • To ContractInput: containment via contracts; diagram multiplicity 0..*.

  • To DotInstance: containment via dots; diagram multiplicity 1..*.

  • To ExposedAnchor: containment via exposedAnchors; diagram multiplicity 0..*.

  • To Wire: containment via wires; diagram multiplicity 0..*.

Shape example from the reviewed Java compatibility corpus (not a runnable deployment)
{
  "apiVersion": "dot.mare6g.eu/v1",
  "kind": "Composition",
  "id": "00000000-0000-4000-8000-000000000001",
  "name": "example",
  "version": "v1",
  "dots": [
    {
      "name": "metrics",
      "source": "repository://Example@1.0.0",
      "dotId": "Example@1.0.0",
      "dotVersion": "1.0.0"
    }
  ]
}

ContractInput

Make an authoritative Contract document available to composition resolution.

Reference the originating DOT instead of copying its Contract declaration or payload into a consumer. The owner supplies the pinned URL and digest. Historical wrapper sources remain a compatibility path, not a fallback when an owning declaration is missing.

Select one canonical DOT release for a named role in a composition.

Use the instance name in graph references and the DOT identity for catalogue resolution. A qualified source must agree with the selected DOT metadata. Choose a deployment ID rather than a manifest-type label; dependencies express readiness order, not interface compatibility or application data flow.

Materializer

Turn a resolved wire value or local input file into declared consumer configuration.

A file destination can copy a source file or inject a resolved value at a JSON Pointer; injection couples valueFrom with that pointer. An environment destination names a declared variable and has no source file. URI templates transform the selected value, not arbitrary runtime state. These actions configure a connection; they do not translate protocols.

Java authority | Generated JSON Schema

JSON field Value Base presence Meaning and constraints

type

string

Required

Destination mechanism used to supply configuration to the consumer. allowed: "CONFIG_FILE", "ENVIRONMENT_VARIABLE".

source

string

Conditional / optional

Local source file for a file-based materialization. minimum length: 1.

valueFrom

string

Conditional / optional

Which resolved endpoint, operation or channel value to use for injection. allowed: "ENDPOINT_URL", "OPERATION_URL", "ENDPOINT_HOST", "ENDPOINT_HOST_PORT", "ENDPOINT_PORT", "CHANNEL_ADDRESS".

uriTemplate

string

Conditional / optional

URI template applied to the selected value through its value variable.

target

MaterializerTarget

Required

Exact instance, service and declared configuration destination receiving the result.

Relationships

  • To MaterializerTarget: containment via target; diagram multiplicity 1.

  • To MaterializerType: typed association via type; diagram multiplicity 1.

  • To MaterializerValueFrom: typed association via valueFrom; diagram multiplicity 0..1.

  • From Wire: containment via materializer; diagram multiplicity 0..1.

  • From Wire: containment via materializers; diagram multiplicity 0..*.

Shape example from the reviewed Java compatibility corpus (not a runnable deployment)
{
  "type": "ENVIRONMENT_VARIABLE",
  "valueFrom": "ENDPOINT_URL",
  "target": {
    "instance": "client",
    "service": "api",
    "environmentVariable": "API_URL"
  }
}

Wire

Connect a provided Anchor to a required Anchor and declare how the consumer receives its connection details.

The arrow expresses logical provision, not necessarily packet direction. Parameter, endpoint, security and materializer choices must agree with the resolved interfaces. Use the singular or plural materializer form, not both. A compatible declaration or configured connection is not proof of network reachability or a successful live operation.

WireSecurity

Bind security requirements of the selected Contract operation to consumer inputs.

Bindings must satisfy a supported complete security requirement alternative, not merely name a familiar authentication technology. Resolution checks declarations; successful authentication, authorization and policy behavior require separate live evidence.
