Identity and capabilities

How to read this reference explains full objects versus ID-only views, conditional fields and validation boundaries.

Dot

Describe one reusable software product or component: its identity, capabilities, interfaces and supported deployment alternatives. A DOT definition is not a running instance or a complete multi-tool use case.

Keep one canonical product definition for the selected tool release. A composition selects instances and deployments, connects Anchors and supplies use-case inputs; do not copy product definitions for each scenario. The CLI deploys from the selected dot.json, not from nearby Dockerfiles or manifests. Java validation checks the aggregate and its declared relationships; catalogue resolution, verified Contract downloads and live acceptance are separate checks.

Java authority | Generated JSON Schema

JSON field Value Base presence Meaning and constraints

id

string

Required

Stable, case-sensitive component identity. A release-qualified identity must agree exactly with name and version. Legacy textual and UUID-shaped keys remain readable, but are not automatic aliases for a different catalogue entry. minimum length: 1; pattern restrictions (see schema).

name

string

Required

Readable product or component name, kept separate from the bundle directory and runtime-instance name. For a qualified identity, changing this name also changes the identity relationship that must be reviewed. minimum length: 1.

version

Version

Required

Release of the represented software, not a revision counter for catalogue edits. Image packaging tags, Helm chart versions and Contract-language versions are separate. Label unreleased planning, source-adapted and test components honestly. pattern restrictions (see schema).

description

string

Conditional / optional

Optional human explanation of purpose, intended use and important limitations. It does not replace machine-readable Contracts, deployment inputs or acceptance evidence.

groups

array of string

Conditional / optional

Open classification labels rather than a closed domain enum. Ownership labels such as internal and external are interpreted by workflows; they do not grant permissions or establish production maturity.

metadata

Metadata

Required

Audit timestamps for this definition. Java construction provides initial values, but raw JSON still needs the required timestamp properties; metadata is not live deployment state.

skills

array of Skill (ID reference)

Required

Capability references serialized as ID-only objects. Choose at least one meaningful catalogue capability; its label and description belong to the Skill catalogue rather than being repeated in every DOT. minimum items: 1.

contracts

array of (Contract (ID reference) or Contract)

Required

Authoritative interface declarations owned by this exact DOT release. Published catalogue roots need complete URL-backed declarations. References to dependency interfaces belong on Anchors with an explicit origin, not as copied declarations here.

anchors

array of Anchor

Conditional / optional

Embedded logical integration points provided or required by the component. Their IDs are local to this DOT and are the keys used by service bindings and composition wires; addresses and credentials do not belong here.

runtimes

array of Runtime

Required

Alternative ways the component can run on its supported platforms. A deployment instance chooses one named deployment; declaring several alternatives does not request that all of them be launched.

Relationships

  • To Metadata: containment via metadata; diagram multiplicity 1.

  • To Skill: ID/name reference via skills (ref); diagram multiplicity 1..*.

  • To Version: containment via version; diagram multiplicity 1.

  • To Anchor: containment via anchors; diagram multiplicity 0..*.

  • To Contract: containment via contracts; diagram multiplicity 0..*.

  • To Runtime: containment via runtimes; diagram multiplicity 0..*.

  • From DotInstance: ID/name reference via dotId / source.

Metadata

Record when a domain definition was created and last updated. These are audit values for the authored record, not workload start times or health observations.

Java constructors and builders initialize timestamps, but authors of raw JSON must supply the properties required by the generated schema. Callers manage subsequent updates; changing another field does not automatically refresh updated. The model does not enforce chronological ordering between these two timestamps or turn them into a version history.

Java authority | Generated JSON Schema

JSON field Value Base presence Meaning and constraints

created

string

Required

Instant at which this definition record was created, serialized as an offset-bearing date-time. Keep it distinct from the release date of the represented software and from a deployment creation time. format: date-time; pattern restrictions (see schema).

updated

string

Required

Instant recorded for the latest authored change. Update it deliberately when appropriate; it is not an automatically maintained clock, a lock digest or proof that a live instance matches the definition. format: date-time; pattern restrictions (see schema).

Relationships

  • From Dot: containment via metadata; diagram multiplicity 1.

Skill

Name a reusable, high-level capability so that components can be classified and discovered by what they do. A Skill is not executable code, an API operation or a deployment recipe.

A standalone Skill has its own descriptive metadata, while Dot.skills serializes only its identity. The catalogue resolves that identity to the authoritative label, description and capability category. Domain reference validation checks the key; repository validation checks that the referenced capability exists and is not merely a category asset.

Java authority | Generated JSON Schema

JSON field Value Base presence Meaning and constraints

description

string

Conditional / optional

Optional explanation of the capability and its scope. Describe the ability without duplicating the interface Contract or claiming that a runtime has been verified.

id

string

Required

Stable, case-sensitive capability key. Moving a catalogue file or changing a display label must not silently create a different identity; unknown keys are not interpreted as names. minimum length: 1; pattern restrictions (see schema).

name

string

Required

Human-readable capability label for a complete Skill entity. It is omitted from the ID-only reference view inside a DOT. minimum length: 1.

  • From Dot: ID/name reference via skills (ref); diagram multiplicity 1..*.

Version

Carry a semantic software version or the special latest selector as a single JSON string. Use it where the owning model needs a software or platform version rather than a free-form label.

The Java default is 0.0.0; it is not evidence of a released component. Concrete values follow SemVer precedence, including prereleases; build metadata is ignored for precedence comparisons. The latest selector sorts after concrete versions and delegates selection to its context, so it is not an immutable artifact pin. Contract.version is a separate document-language string, not this value object. There is no nested JSON value property.

Java authority | Generated JSON Schema

JSON representation: string; pattern restrictions (see schema).
