Contracts and Anchors

How to read this reference explains full objects versus ID-only views, conditional fields and validation boundaries.

Anchor

Give one provided or required interaction a stable, DOT-local integration key. Compositions connect these logical points; deployment service bindings connect locally provided, non-brokered interfaces to named ports.

Choose exactly one communication mode: a Contract operation, a supported provider-neutral requirement, or explicit contractless communication facts. Do not duplicate direction, protocols or media types for a Contract-backed Anchor. Aggregate validation checks references, selector syntax and deployment bindings; the CLI resolves actual Contract operations. Declarations, optional semantic labels and a compatible wire are not live reachability, authentication or production acceptance.

JSON field Value Base presence Meaning and constraints

id

string

Required

Stable key used by composition endpoints and deployment Anchor bindings. Prefer meaningful DOT-local kebab-case names. Legacy UUID strings remain readable, but display names and selectors are not aliases for this key. minimum length: 1; pattern restrictions (see schema); conditional constraints (see schema).

name

string

Required

Readable label for the interaction. It can help an author choose an Anchor, but wires and service bindings reference id rather than this display label. minimum length: 1.

role

AnchorRole

Required

Whether this component offers the interaction or depends on it. This logical provider/consumer relationship is independent of which participant initiates a network request or the direction of payload flow. allowed: "PROVIDES", "REQUIRES".

semanticTypes

array of string

Conditional / optional

Optional defined vocabulary identifiers for domain meaning, not API documentation URLs or payload-schema pointers. The CLI treats them as opaque URI strings: nonempty lists on both sides must intersect exactly; an absent list imposes no restriction and supplies no semantic proof. It performs no ontology inference.

contract

AnchorContract

Conditional / optional

Reference to an authoritative Contract plus one standard-specific operation selector. Local ownership resolves through this DOT; external ownership requires the exact originating DOT source. Communication facts come from the selected document.

requirement

AnchorRequirement

Conditional / optional

Provider-neutral, versioned requirement on a REQUIRES Anchor. A composition chooses and verifies the concrete provider. It cannot be combined with a Contract reference or explicit contractless communication facts. exact value "OIDC_DISCOVERY_1_0".

direction

AnchorDirection

Conditional / optional

Payload-flow direction relative to the declaring DOT, only for a contractless Anchor. Do not infer it solely from PROVIDES or REQUIRES; request/response interactions and transport initiation are different concepts. allowed: "INGRESS", "EGRESS", "BIDIRECTIONAL".

protocols

array of string

Conditional / optional

Explicit communication protocols for a contractless interaction. Declare the actual supported boundary rather than treating a semantic label, file format or service name as a protocol.

mediaTypes

array of string

Conditional / optional

Explicit payload media types for a contractless interaction. These describe the exchanged representation, not a full payload schema or a guarantee that another component understands its domain meaning.

{
  "id": "build-information",
  "name": "build-information",
  "role": "PROVIDES",

  }
}

AnchorContract

Select one composable interaction from an existing authoritative Contract. Use it on an Anchor rather than copying an interface document or declaring another product-owned Contract.

The referenced identity, origin and selector must agree. OpenAPI and AsyncAPI use operation references; Protobuf uses a service method and GraphQL uses a root-field coordinate. A data-schema pointer is not an operation. Java aggregate validation checks local relationships and selector syntax; the CLI resolves the exact originating declaration, verifies its bytes and checks the selected operation. Matching shapes in independently authored Contracts do not make their identities interchangeable.

AnchorDirection

Describe the direction of data flow at a contractless interaction relative to the declaring DOT. It fills in a communication fact that cannot be derived from an authoritative Contract.

Ingress means flow into the DOT, egress means flow out, and bidirectional means both. Keep this separate from the Anchor provider/consumer role and from the direction of a TCP connection. The current contractless matcher requires complementary directions alongside compatible protocols and media types; the enum alone proves none of those other conditions.

AnchorRequirement

State a narrow, versioned provider-neutral interface requirement instead of hard-coding a particular producer Contract. The current supported profile concerns OIDC discovery.

Use it only on a REQUIRES Anchor and do not combine it with Contract or explicit contractless fields. A composition wire selects the real provider and the CLI checks the supported requirement profile against its verified Contract. This is not an arbitrary semantic label, automatic provider discovery or full OIDC, TLS and production IAM acceptance.

AnchorRole

Distinguish a component that provides an interaction from one that requires it. This is the logical relationship used to connect a provider Anchor to a consumer Anchor.

Role is not payload-flow direction, server/client process type or permission to call an API. A component can provide an HTTP operation even when another component initiates the request. Complementary roles do not replace Contract identity, operation, protocol, security or live acceptance checks.

JSON representation: string; allowed: "PROVIDES", "REQUIRES".

Contract

Identify one authoritative interface specification and the exact downloadable document that describes it. Anchors select interactions from that document instead of copying its protocol and payload details.

Keep the declaration at its owning DOT and retain that identity when another component consumes or implements the interface. Qualified identities must agree with the exact owning DOT release, standard and local Contract name. Complete definitions carry a verified URL/hash payload; an ID-only reference view is not a publishable owned declaration. Domain validation checks declaration relationships and metadata, while the CLI fetches, hashes and parses the document and resolves operations. Neither establishes that a producer implements the interface at runtime.

DataFormat

Required

Encoding of the downloaded document, not its transport protocol. It must be supported by the chosen standard; an extension or a matching file name does not establish compatibility. allowed: "YAML", "JSON", "PROTOBUF", "GRAPHQL".

Required

Stable interface identity, independent of its download URL. Catalogue identities include the originating DOT release and the exact standard/name suffix. Consumers retain this key rather than minting a consumer-owned copy. minimum length: 1; pattern restrictions (see schema).

name

string

Required

Local, case-sensitive interface name within the owning DOT. It is part of the qualified identity, not a hostname, an operation selector or the upstream API release number. minimum length: 1.

payload

Required

Structured raw-document location and integrity pin. The specification bytes are downloaded separately; this property does not embed the document or provide a local Contract-folder fallback.

Required

string

Conditional / optional

Version of the document language declared by the verified payload: the OpenAPI or AsyncAPI marker, or the native Protobuf syntax/edition. Do not copy a tool release or info.version. GraphQL SDL has no such marker and omits this property.

ContractStandard

Choose the interface-description language used by a Contract. This choice determines how the document is parsed, which encoding is valid and how an Anchor operation is selected.

Use the exact serialized values shown by the generated enum reference; alternative capitalization, whitespace and Java constant names are not aliases. Standard version and document format remain separate properties. Selecting a supported language is not a claim that every optional feature or live protocol behavior is implemented by the current CLI.

DataFormat

Identify the serialization format of a document or manifest payload. It describes how bytes are represented, not the purpose of the interface or the infrastructure that runs it.

The owning field determines which formats are valid. Contract formats must match their Contract standard, and Docker Compose, Kubernetes manifests and Helm values accept only their supported structured text encodings. A format enum does not add a new deployment mechanism, turn a Vagrantfile into YAML or describe an HTTP media type.

JSON representation: string; allowed: "YAML", "JSON", "PROTOBUF", "GRAPHQL".

Payload

Locate an exact raw document and pin its bytes. This shared value describes a downloadable file, never the address of a deployed API or an instruction to execute it.

Contract.payload, DockerCompose.payload, KubernetesManifest.payload, Vagrantfile.payload, HelmValues.payload and EnvFile.payload use this same value; ConfigFile.payload optionally uses it too. There is no inline-text, Base64 or adjacent-file fallback. URLs must be absolute HTTPS without embedded credentials or fragments. The current-source CLI reuses bounded verification and a digest-addressed cache outside DOT bundles, rehashes cached bytes and fails on corruption. Offline use needs every required document already cached; it does not prove that an origin is currently available. Java/schema validity alone does not download bytes. A matching hash establishes byte identity, not publisher authority, license permission, safe execution, producer conformance or live availability.

JSON field Value Base presence Meaning and constraints

sha256

string

Required

Lower-case SHA-256 of the exact downloaded bytes. Formatting or newline changes alter this pin even if a reader considers the document equivalent; review changed bytes rather than silently replacing the expected digest. minimum length: 64; maximum length: 64; pattern restrictions (see schema).

url

string

Required

Download location for the raw document, not an HTML viewer, deployed endpoint, local path or operation fragment. The owner determines whether the verified bytes are a Contract, manifest, values, dotenv or default configuration document. format: uri; pattern restrictions (see schema).
