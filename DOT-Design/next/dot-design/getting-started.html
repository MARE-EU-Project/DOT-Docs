Getting started

Run your first DOT on Linux amd64 using the selected CLI release v0.4.0 and the existing Prometheus definition. You need Bash, Git, GitHub CLI (gh), curl, jq, SHA-256 utilities, and Docker with Docker Compose. No Java, Go, Kubernetes, or Task is needed for this path.

This example runs Prometheus 3.15.1 on port 18909. Allow time for initial image and Contract downloads. Use an isolated development host: the Compose manifest publishes unauthenticated HTTP on all host interfaces. Restrict access using your host firewall. Cleanup deletes the example’s metrics data.

Install the released CLI

Authenticate with an account granted access to the private MARE repositories and releases. From a workspace directory:

set -o pipefail
gh auth login &&
gh auth setup-git &&
mkdir -p dot-quickstart-download &&
cd dot-quickstart-download &&
gh release download v0.4.0 --repo MARE-EU-Project/DOT-CLI \
  --pattern dotx-0.4.0-linux-amd64 --pattern SHA256SUMS &&
mkdir -p "$HOME/.local/bin" &&
sha256sum dotx-0.4.0-linux-amd64 |
  grep -Fx -f - SHA256SUMS &&
  install -m 0755 dotx-0.4.0-linux-amd64 "$HOME/.local/bin/dotx" &&
export PATH="$HOME/.local/bin:$PATH" &&
dotx version &&
cd ..

The checksum must match the downloaded binary’s exact filename and bytes; installation is skipped if its entry is missing or wrong. Stop on any error. Expected version: dotx 0.4.0. Add the PATH export to your shell profile for future sessions. The release also provides an SBOM and build/acceptance revision manifest.

Check out the catalogue

Only the independently cloneable catalogue is needed. Pin the acceptance revision recorded in this CLI release’s manifest, then check your Docker access:

gh repo clone MARE-EU-Project/DOT-Repository &&
cd DOT-Repository &&
git checkout --detach 2b17ee681fbe8eed6822834484f87149b32fc772 &&
docker info &&
docker compose version

Run the following blocks in the same Bash shell from the DOT-Repository root. Run each block only after the preceding block succeeds. The selected descriptor embeds its Compose manifest; no neighbouring Compose file is inferred.

Select and validate

The selection block generates and prints a distinct runtime name. Keep that name and the same shell for cleanup. To choose your own name, first run DOT_NAME=my-prometheus-lab and ensure it belongs only to your run; a random default is not permission to adopt an existing project. For a different host port, run export DOTX_HTTP_PORT=18919 before the selection block.

DOT_REPOSITORY="${DOT_REPOSITORY:-$PWD}" &&
DOT_DEFINITION="$(dotx repository resolve Prometheus@3.15.1 --repository "$DOT_REPOSITORY")" &&
DOT_BUNDLE="$(dirname -- "$DOT_DEFINITION")" &&
DOT_NAME="${DOT_NAME:-dot-quickstart-$RANDOM-$RANDOM}" &&
DOTX_HTTP_PORT="${DOTX_HTTP_PORT:-18909}" &&
DOT_PROJECT_FILTER="label=com.docker.compose.project=$DOT_NAME" &&
export DOTX_HTTP_PORT &&
printf 'Selected: Prometheus 3.15.1; instance %s; host port %s. Keep this shell for cleanup.\n' "$DOT_NAME" "$DOTX_HTTP_PORT"
(
set -euo pipefail
printf 'Checking the definition and previewing Docker Compose; nothing starts yet...\n'
dotx validate "$DOT_BUNDLE" --schema "$DOT_REPOSITORY/Schema/schema.json" \
  --profile reusable
dotx inspect "$DOT_BUNDLE"
dotx deploy "$DOT_BUNDLE" --deployment docker-compose --name "$DOT_NAME" --dry-run
)

Validation checks the schema, official HTTPS OpenAPI Contract and SHA-256, Anchor selectors, and reusable deployment bindings. Inspection shows deployment choices. The exact ID docker-compose selects only that mechanism. Dry-run prints its commands; it does not prove that a service is running.

Deploy and verify

dotx deploy "$DOT_BUNDLE" --deployment docker-compose --name "$DOT_NAME" \
  --env "DOTX_HTTP_PORT=$DOTX_HTTP_PORT"

Wait up to 60 attempts (each HTTP attempt has a two-second timeout), then verify the service’s build-information API and version:

(
set -euo pipefail
ready=false
started=$SECONDS
next_notice=$SECONDS
printf 'Checking Prometheus readiness on port %s...\n' "$DOTX_HTTP_PORT"
for ((attempt=0; attempt<60; attempt++)); do
  if curl --fail --silent --max-time 2 \
    "http://127.0.0.1:$DOTX_HTTP_PORT/-/ready"; then
    ready=true
    break
  fi
  if ((SECONDS >= next_notice)); then
    printf 'Waiting for Prometheus: attempt %s/60, %ss elapsed\n' "$((attempt + 1))" "$((SECONDS - started))"
    next_notice=$((SECONDS + 5))
  fi
  sleep 1
done
if ! $ready; then
  printf 'Prometheus readiness timed out. Run the cleanup block before retrying.\n' >&2
  exit 1
fi
curl --fail --silent --show-error --max-time 5 \
  "http://127.0.0.1:$DOTX_HTTP_PORT/api/v1/status/buildinfo" |
  jq -e '.status == "success" and .data.version == "3.15.1"'
printf 'Verified: Prometheus 3.15.1 answered its official API. Open http://127.0.0.1:%s/\n' "$DOTX_HTTP_PORT"
)

Expected: Prometheus Server is Ready., true from jq, then Verified: Prometheus 3.15.1 answered its official API. and your browser URL. Check runtime status:

dotx ps

Expect a running workload. Open http://localhost:18909 (or your chosen port) to view Prometheus.

The build-information Anchor selects the official OpenAPI operation whose server prefix produces /api/v1/status/buildinfo. The promql-query-api Anchor selects query operations; both bind to the deployed service’s http port. Its scrape-target requirement references Node Exporter’s metrics interface; this first example does not connect another DOT as a scrape target.

The pinned image’s default configuration starts the service. The descriptor declares a Compose-managed prometheus-data volume. Data survives container restarts until the volume is deleted.

Clean up

For Compose, dotx destroy runs down --volumes: it deletes this instance’s containers, network, and named volume, including collected metrics. Use the same DOT_NAME as deployment. Never target another user’s instance.

 
dotx destroy "$DOT_BUNDLE" --deployment docker-compose --name "$DOT_NAME" &&
remaining="$(docker ps -aq --filter "$DOT_PROJECT_FILTER")" &&
test -z "$remaining" &&
remaining="$(docker network ls -q --filter "$DOT_PROJECT_FILTER")" &&
test -z "$remaining" &&
remaining="$(docker volume ls -q --filter "$DOT_PROJECT_FILTER")" &&
test -z "$remaining"

The final checks succeed silently. If interrupted, restore your original selection variables and repeat cleanup. Before closing the shell, note the printed instance name, catalogue checkout and selected port. To recover that same run in a new shell, set DOT_NAME to its original value and DOTX_HTTP_PORT to its original port, change to that same catalogue checkout, then repeat the selection and cleanup blocks. Do not accept a newly generated name for cleanup. Retain the original CLI, cache and Docker context until cleanup is verified. The Zero to Hero tutorial saves these values in a private session file. Downloaded images remain cached.

Next: connect existing DOTs

For the newcomer evaluation route, continue with one matching prebuilt kit and Docker monitoring. It keeps the same binary and catalogue and requires no contributor build. The following Kubernetes example is a separate source-contributor/operator route.

For the existing Keycloak/APISIX/OAuth composition, use a full DOT-Design checkout with initialized submodules; see Contributor guide. From the DOT-Design root, with dotx on PATH:

This follow-up uses the source-built development CLI. Install the checked-out CLI using the contributor toolchain before continuing; released binaries do not necessarily implement the current commands or lock format.

composition=DOT-Repository/Compositions/keycloak-apisix-oauth/composition.yaml
task cli:install
dotx compose lock "$composition" --check
dotx compose inspect "$composition" --locked
dotx compose apply "$composition" --locked --dry-run

The three wires connect Keycloak discovery to APISIX, Keycloak’s token endpoint to the OAuth client, and APISIX’s protected operation to that client. The resolved composition resolves endpoints and configuration. Live acceptance additionally proves anonymous rejection and authenticated access; the harness prepares Kubernetes, native Secrets, and workloads. Follow Guided demo and Verification and examples for that path.

To author a component, continue with Authoring Anchors. For development toolchains and local/GitHub CI gates, use Contributor guide.

Troubleshooting

Symptom Action

Release or clone returns 404/403

Check gh auth status and organization repository access, including SSO authorization if required. Run gh auth setup-git for HTTPS cloning.

CLI missing or wrong version

Check command -v dotx; put $HOME/.local/bin first on PATH.

Docker permission denied

Check docker info as your user. Ask the administrator for the intended Docker access, then log in again. Docker group access grants host-level power.

Compose unavailable

Install the Compose plugin/package for your Docker distribution and verify docker compose version. The legacy docker-compose executable is insufficient.

Port already allocated

Clean up the failed example, select a free DOTX_HTTP_PORT, and deploy again with the same name and explicit --env override.

Contract download or digest check fails

Check network/proxy access to the declared URL. Never bypass its digest. Private raw GitHub URLs require MARE_READ_ONLY_TOKEN or GITHUB_TOKEN; gh login alone does not supply those to dotx. Use --offline only with matching verified local Contract assets.

Readiness or version fails

Use the instance-scoped logs below and dotx ps --all, check the selected image/port, then clean up. No local Compose file is required for this diagnostic.

Interrupted cleanup

Restore the original name and catalogue path, repeat cleanup, and inspect resources carrying com.docker.compose.project=$DOT_NAME.

Read only this instance’s logs

Keep the original DOT_NAME. This block discovers containers by their Compose project label and reads bounded logs. It works from the catalogue checkout: docker compose -p …​ alone would not locate the descriptor’s downloaded Compose document. No resources are changed or removed.

(
set -euo pipefail
containers="$(docker ps -aq --filter "label=com.docker.compose.project=$DOT_NAME")"
if test -z "$containers"; then
  printf 'No containers found for this instance: %s\n' "$DOT_NAME" >&2
  exit 1
fi
while IFS= read -r container; do
  printf '\nLogs for this instance container: %s\n' "$container"
  docker logs --tail=100 "$container"
done <<< "$containers"
)

If Docker access fails or no matching container is found, the block fails; it does not query another instance. Use the same lesson’s cleanup command and retain the original context until cleanup is verified.
