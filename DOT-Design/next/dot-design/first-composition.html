Run your first composition

Run two tools together on Docker. Node Exporter provides metrics. Prometheus collects them. You’ll preview the deployment, check that Prometheus received a sample, and remove both tools.

Before you start

Complete Quick Start first. This tutorial adds a version-matched catalogue and a real, two-tool deployment to that setup. You can reuse an existing matching installation.

Use Bash, curl, jq, ss (from iproute2), GitHub CLI (gh), and Docker Engine 28 or later on Ubuntu 26.04 amd64. Run the commands on the Docker host, with Docker accessible to your normal user. Keep the same Bash terminal open through cleanup so GRAPH and PORT stay set. Keep the same Docker context and daemon. The graph uses Docker images and needs no Compose plugin. See Requirements.

Keep the current-source CLI installed by Quick Start. Named catalogue compositions are an unreleased source feature, absent from release 0.5.0. If you reuse an installation, run command -v dotx to check which executable your shell selects. For a Go install, the module version from go version -m "$(command -v dotx)" should end in the first 12 characters of ad990e269daa5e2b39f95aafa2677ad516047513. For manual installation, select the Quick Start source commit in Install with Go. The single-DOT quickstart remains available separately.

Check your setup

dotx version
dotx tool check docker &&
docker version --format '{{.Server.Version}}'

Expect docker: ready and a Docker server version of 28 or later. No manual catalogue clone is required. dotx retrieves a verified snapshot of DOT-Repository using the Git credentials configured in Quick Start. The first catalogue command prints its exact revision and caches the selected composition, DOT definitions, reviewed lock and non-secret configuration files. If access fails, check gh auth status and read access to DOT-Repository, then repeat gh auth setup-git --hostname github.com. Your repository credentials stay with GitHub CLI.

The selection stays pinned through preview, deployment, probes and cleanup. Changes to main do not change a recorded selection. The commands below set REPOSITORY_VERSION to the tested catalogue commit unless you have already set it. If an earlier session set a different revision, run unset REPOSITORY_VERSION before this walkthrough to use its tested default. An active deployment cannot be redirected to another revision. After verified destroy, a later run can select the current catalogue again. Existing local-file commands and explicit --repository selections remain available for authors.

Validate, view the topology, and preview

export REPOSITORY_VERSION="${REPOSITORY_VERSION:-ffcfacab7dac451cf7f099dd3ef9b3c752aecee6}"
GRAPH=node-exporter-prometheus-monitoring
PORT="${PORT:-19040}"

dotx compose validate "$GRAPH" --locked &&
dotx compose topology "$GRAPH" --locked &&
dotx compose apply "$GRAPH" --locked --dry-run \
  --forward "prometheus/promql-query-api=$PORT"

Continue only if validation, topology, and preview all succeed. The topology shows the two tools as Vertices. The Edge joins them, and its node-metrics-to-prometheus Channel connects the metrics interfaces, called Connectors. See DOTs for Dummies for the model. Expect two Docker image deployments. The preview shows -p 127.0.0.1:19040:9090 for Prometheus at the default port. The preview creates no workloads and writes no lifecycle state. Validation and preview can populate the cache with verified inputs.

Save the cleanup command and check the port

Keep this cleanup command handy before you apply. If apply reports existing recorded state or a different recorded source snapshot, stop and leave that deployment in place. If a new apply fails, read its rollback output and run dotx compose status "$GRAPH". If status reports has no recorded catalogue selection or has no applied state after rollback, there is nothing to destroy. If your attempt left a state record or reported incomplete rollback, run the cleanup command. A managed network may remain even when status lists no running tools.

dotx compose destroy "$GRAPH"

Before deploying, check the selected port from the same host:

ss -H -ltn "sport = :$PORT"

No output means no TCP listener was found at the time of the check. If it shows a listener or Docker reports the port is occupied during apply, leave that listener alone. Clean up any state created by your attempt, choose another unused port with PORT=19041 (for example), then repeat the port check and preview. Use that same PORT for apply and the query.

Apply and verify

Run apply after reviewing the preview for your chosen port on the isolated development host.

dotx compose apply "$GRAPH" --locked \
  --forward "prometheus/promql-query-api=$PORT"

The first apply downloads any missing images from Docker Hub. Wait for Composition applied: node-exporter-prometheus-monitoring, then query Prometheus for a successful Node Exporter scrape:

curl -fsSG --max-time 5 "http://127.0.0.1:$PORT/api/v1/query" \
  --data-urlencode 'query=up{job="node-exporter"} == 1' |
  jq -ser '.[0].data.result[0].value[1] | select(. == "1")' &&
  printf 'Verified: Prometheus scraped Node Exporter.\n'

Expect 1 followed by the verification message. If there is no result or curl reports an empty reply, wait a few seconds and retry. Prometheus may still be starting or waiting for the first scrape. If it still fails after 90 seconds, check status and clean up. This example observes the Node Exporter container.

The managed cache preserves the readability of published, non-secret input files even when your shell uses umask 077; no manual cache-file edits are needed. Cache contents and runtime state stay private to your user.

Inspect and clean up

Run these commands for the deployment you just created. Use the same terminal, Docker context and daemon as apply.

dotx compose status "$GRAPH"
dotx compose destroy "$GRAPH"

Expect a message beginning with Cleanup verified: 2 Docker deployment(s). The check covers the recorded containers, managed network and disposable volumes. Repeat the port check to confirm the demo listener is gone.

Continue with Create a composition to make a separate draft from the monitoring template, review its lock, and view its topology. DOTs in Action walks through extending the graph.

If you’re participating in the partner beta, follow the feedback instructions after cleanup.
