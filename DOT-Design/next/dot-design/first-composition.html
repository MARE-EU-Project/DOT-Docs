Run your first composition

Run Node Exporter and Prometheus together on Docker. In the Next source graph, the node-exporter-to-prometheus Edge joins the two Vertices. Its node-metrics-to-prometheus Channel connects the node-metrics and scrape-target Connectors. Use the prometheus-query exposure for the promql-query-api Connector to verify the scrape.

Before you start

Complete Quick Start first. This tutorial adds a version-matched catalogue and a real, two-tool deployment to that setup. You can reuse an existing matching installation.

Use Bash, Git, Go, curl, ss (from iproute2), and Docker Engine on Ubuntu 26.04 amd64. Run these commands on the Docker host. See Setup for Git and Go. Use a Git credential helper or SSH configuration with read access to both private MARE repositories. The first run can download images and Contract documents.

Use Docker Engine 28 or later. The graph uses Docker images and needs no Compose plugin.

Prepare the catalogue

Keep the source dotx installed by Quick Start: the Connector format on main requires the matching source CLI. A published release requires its matching catalogue pair below. In a fresh working directory, clone the catalogue and enter it:

git clone https://github.com/MARE-EU-Project/DOT-Repository.git &&
cd DOT-Repository &&
git checkout --detach "${REPOSITORY_VERSION:-origin/main}" &&
dotx version &&
git rev-parse HEAD &&
dotx tool check docker

Already have a checkout? Enter its root and run the last three checks instead of cloning again. Keep the same Bash terminal and Docker context through cleanup. Record the printed CLI version and catalogue commit. If repository access fails, check your Git credentials before continuing. The full composition uses the checkout; Hello World’s single-definition download did not create one.

For an exact, reproducible version pair, or a fresh installation without Quick Start, expand the instructions below. The normal route above uses catalogue main; a released CLI can lag behind it.

Pinned versions and fresh installation

For a reproducible setup, choose one matched pair below before installing or cloning. The source pair uses the Vertex, Edge and Channel model and publishes Prometheus on IPv4 loopback.

CLI_VERSION=90c1cfe2fdebffe3ea820b82810c13e67ad8a60c
REPOSITORY_VERSION=d572d56a79650c702df639ed9add0bf095ea0734

For the published 0.5.0 CLI, use its release-manifest pair:

CLI_VERSION=v0.5.0
REPOSITORY_VERSION=7a196ddb7dd4f7e18d720f00818a1367d2401bdb

Install your selected CLI_VERSION using Manual installation. Keep the same terminal so both variables remain set, then use the catalogue setup above. That setup uses REPOSITORY_VERSION when supplied and main otherwise. The manual install defaults to latest when CLI_VERSION is unset.

For an existing checkout, preserve local edits and run the following from its root after installing the matching CLI:

git fetch origin &&
git checkout --detach "${REPOSITORY_VERSION:?select a matched pair}" &&
dotx version &&
git rev-parse HEAD &&
dotx tool check docker

A source build’s version ends with the first 12 characters of CLI_VERSION; a released build reports its release version. Check the printed catalogue revision against REPOSITORY_VERSION. A schema or lock mismatch means the pair needs checking before you continue.

For a single-service alternative, use the single-DOT quickstart.

Validate, view the topology, and preview

GRAPH=Compositions/node-exporter-prometheus-monitoring/composition.yaml
PORT="${PORT:-19040}"

dotx compose validate "$GRAPH" --locked &&
dotx compose topology "$GRAPH" --locked &&
dotx compose apply "$GRAPH" --locked --dry-run \
  --forward "prometheus-query=$PORT"

Expect two Docker image deployments and the node-metrics-to-prometheus Channel. The preview shows -p 127.0.0.1:19040:9090 for Prometheus at the default port. The preview creates no workloads and writes no lifecycle state. Validation and preview can populate the cache with verified inputs.

Save the cleanup command and check the port

Keep this cleanup command handy before you apply. After your apply attempt, run it if your run created state, even if the query fails. If apply reports a previously applied composition, leave that run to its owner.

dotx compose destroy "$GRAPH"

Before deploying, check the selected port from the same host:

ss -H -ltn "sport = :$PORT"

No output means no TCP listener was found at the time of the check. If it shows a listener or Docker reports the port is occupied during apply, leave that listener alone. Clean up any state created by your attempt, choose another unused port with PORT=19041 (for example), then repeat the port check and preview. Use that same PORT for apply and the query.

Apply and verify

Run apply after reviewing the preview for your chosen port on the isolated development host.

dotx compose apply "$GRAPH" --locked \
  --forward "prometheus-query=$PORT"

After apply succeeds, paste this block. It waits up to 90 seconds for a successful scrape and prints the matching Prometheus response.

(
  deadline=$((SECONDS + 90))
  sample='"value"[[:space:]]*:[[:space:]]*\[[0-9.]+[[:space:]]*,[[:space:]]*"1"[[:space:]]*\]'
  while (( (remaining = deadline - SECONDS) > 0 )); do
    timeout=$((remaining < 3 ? remaining : 3))
    if reply=$(curl -fsSG --max-time "$timeout" \
      "http://127.0.0.1:$PORT/api/v1/query" \
      --data-urlencode 'query=up{job="node-exporter"} == 1' 2>/dev/null) &&
      [[ $reply =~ $sample ]]; then
      printf '%s\n' "$reply"
      exit 0
    fi
    (( SECONDS + 2 < deadline )) || break
    sleep 2
  done
  printf '%s\n' 'No successful scrape yet. Run status, then clean up.' >&2
  exit 1
)

Expect a sample for node-exporter with value "1". Before the first scrape, Prometheus can return an empty result. If the check times out, inspect status and clean up. This example observes the Node Exporter container.

If Prometheus exits with a permissions error on /etc/prometheus/prometheus.yml, check the catalogue file. A checkout created with umask 077 can leave it at mode 0600, unreadable by the container. After cleanup, set this public fixture to mode 0644 from the catalogue root, then apply again:

chmod 0644 \
  Compositions/node-exporter-prometheus-monitoring/runtime/prometheus.yml

Inspect and clean up

dotx compose status "$GRAPH"
dotx compose destroy "$GRAPH"

Expect destroy to report verified cleanup of both Docker deployments and their managed network and disposable volumes. You can repeat the port check to confirm the demo listener is gone.
