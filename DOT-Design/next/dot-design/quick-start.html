Quick Start

On Ubuntu 26.04 LTS, have Git, GitHub CLI (gh) and Docker Engine installed. Open a Bash terminal as your normal user on the Docker host. Run docker info before continuing. For a permission error, follow the Docker Linux post-installation instructions. If you change group membership, sign out and back in, then retry docker info. For a remote shell, reconnect. See Requirements for the other installation links.

Your GitHub account needs read access to DOT-CLI and DOT-Repository.

Sign in once

gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git --hostname github.com

If you’re already signed in with your project account, skip the login command. Check that your account can read both repositories before installing:

gh repo view MARE-EU-Project/DOT-CLI --json name --jq .name &&
gh repo view MARE-EU-Project/DOT-Repository --json name --jq .name

Expect DOT-CLI and DOT-Repository. If either check fails, run gh auth status and ask your MARE project contact to confirm your access.

Install

The installer prepares missing Go and CA certificates and installs dotx into $HOME/.local/bin. Run it as your normal user; sudo is used only for missing system packages. If you lack sudo access, ask the host administrator to install Go and CA certificates first.

This tutorial uses the installer and CLI build from the same tested commit. Release 0.5.0 does not include dotx run or named compositions. On the first build, Go may download a newer toolchain and dependencies. Wait for dotx installation complete. before running Hello World.

set -o pipefail
CLI_VERSION=ad990e269daa5e2b39f95aafa2677ad516047513
INSTALLER=repos/MARE-EU-Project/DOT-CLI/contents/scripts/install.sh
gh api --hostname github.com "$INSTALLER?ref=$CLI_VERSION" \
  -H 'Accept: application/vnd.github.raw+json' | CLI_VERSION="$CLI_VERSION" bash &&
export PATH="$HOME/.local/bin:$PATH"

If the output reports a disk quota or space error, check free space and quotas for your home directory and /tmp. For a temporary-directory error, create a writable directory on a filesystem with enough space, set TMPDIR to its absolute path, and retry. A second terminal may need the PATH line again.

Run Hello World

dotx run hello-world

Expect Docker’s Hello from Docker! greeting followed by:

DOT completed successfully. Container removed; setup is ready.

The first run may download the official Hello World image. If no local catalogue provides the definition, dotx uses gh to fetch it from the current DOT-Repository default branch. The first-composition guide pins an exact catalogue commit. The container is removed automatically.

If dotx reports cannot access DOT-Repository through GitHub, repeat the repository access checks above. For Docker errors, repeat the docker info check from the prerequisites. If you explicitly selected a repository that lacks Hello World, update that checkout. A dotx run --dry-run preview uses a local or cached catalogue. Preview may fetch verified deployment payloads.

Next: Run your first composition with Node Exporter and Prometheus. For manual installation and reproducible version pins, see Install with Go.

If you’re participating in the partner beta, send any problem to your MARE project contact using the trial record. Include the failing step, the output of dotx version if installed, the catalogue revision if printed, and the error with credentials removed.
