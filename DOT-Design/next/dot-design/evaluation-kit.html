Evaluate DOT with one matching artifact set

An evaluation kit keeps one source-qualified Linux-amd64 CLI, catalogue, schemas and instructions together. It is an evaluation build, not a published release. Its source version label can equal an older release; exact commits and hashes in the kit receipt identify its capabilities.

Participant route

Obtain the kit and its independently recorded outer SHA-256 from your authorized project contact. No public download or redistribution approval is implied. Follow the included START-HERE.md from a fresh private folder. It verifies the complete inventory, installs the binary in that private workspace and extracts the matching local catalogue. Use that binary for the entire attempt.

The first graph is Node Exporter → Prometheus on Docker: inspect the DOTs, create a fresh draft, review topology and lock, deploy, query the real scrape and clean up. Linux amd64, Bash, Docker/Compose, curl and jq are needed. Java, Go, Task and Kubernetes are not participant prerequisites for this graph.

The exporter observes its container rather than the physical host. Its metrics Wire is an explicit HTTP interface, not an invented OpenAPI specification. First validation may download pinned documents; images are a separate runtime download. A warm document cache does not establish offline runtime readiness.

Reserve an exclusive session with the operator. Draft UUIDs alone do not isolate ports, namespaces, inputs or external gateways. Keep the original binary/cache until cleanup is verified; stop on unknown ownership. Never prune unrelated resources. Advanced Contract authoring, safe edit/cancel, graph creation and lock review remain part of the trial protocol.

Operator and maintainer route

From the DOT-Design checkout root, check the private-kit infrastructure:

task testing:adoption:checks

Assembly uses a clean committed source set, existing model packaging and complete asset checks. The kit records pending distribution rights and excludes resolved credentials, caches, runtime state and images. Keep it in a restricted persistent archive outside build directories and retain the independent issuer hash. Standalone checking is data-only: it never executes a supplied binary.

The secure-API walkthrough is a separate Kubernetes operator chapter. The Prometheus portability example has zero Wires and demonstrates independent deployments, not cross-runtime data flow. Actual cross-runtime qualification must identify the intended producer from the consumer context and prove interruption/recovery.

Evidence boundaries

The initial neutral-core inventory maps 77 exported models through existing generated-schema discovery and records reviewed semantic rule families. Its consistency guard does not validate arbitrary DOTs or certify a reader. Known unresolved issues include ownership-group policy disagreement, the narrower raw UUID restriction, raw parsing/presence coverage and complete semantic inventory. Affected neutral-profile publication is blocked until those are resolved.

No human trials, independent implementation or owner approvals are supplied by these checks. Read the remaining release gates before making release or production claims. Stable-tag documentation remains unchanged.
