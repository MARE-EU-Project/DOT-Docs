MARE PoC composition walkthroughs

Start here when presenting DOT composition against MARE use cases. Run commands from DOT-Design with its pinned submodules. These are integration slices, not complete official PoC outcomes. For generic cross-runtime/four-Contract mechanics, use the Docker/Kubernetes demo.

Presenter route: inspect, run, prove, clean up

For a 15-20 minute presentation, show PoC4 first, PoC10 second, and PoC6 only with its adapter/double boundary visible. Avoid new feature changes on the day. Each presenter command uses the same locked composition and live assertions as acceptance; there is no second set of DOT definitions or demo-only success path.

# Run from a real interactive terminal, one example at a time.
task testing:pocs:present:monitoring
task testing:pocs:present:secure-api
task testing:pocs:present:remediation

Each follows five stages: inspect topology → deploy → verify → inspect the running result → clean up. The terminal prints resolved DOT versions, deployments, wires and evidence boundaries. It pauses only after every API assertion passes. While paused, open the printed Prometheus targets page or inspect the redacted result.json; the secure API must still deny anonymous requests. Do not paste access tokens or Secret values into the presentation.

The topology is generated from the locked composition by dotx compose topology, using the MIT-licensed mermaid-ascii 1.6.1 Go library embedded in the binary. There is no Python renderer or separate executable to install. DOTs appear once, with connected Unicode boxes. Parallel wires share a connection labelled W1,W2,…​; the connection legend lists every wire, Contract standard and protocol separately. T links show broker transport endpoints, not extra Anchor wires or invented application publishers. Aligned tables show full instance names, platforms, deployments and versions, plus each connection’s provider, consumer, Contract standard, protocol and name. Long values wrap inside their columns without truncation, using the same width as the graph. Arrows mean logical PROVIDES-to-REQUIRES relationships, not packet direction. The graph reappears after successful live verification.

Interactive diagrams use cyan Kubernetes, magenta Docker and amber connection IDs. Set NO_COLOR=1 or DOTX_TOPOLOGY_COLOR=never for plain output; always forces colour when capturing a demonstration (NO_COLOR and TERM=dumb still disable it). Logs are plain by default. DOTX_TOPOLOGY_WIDTH=80 controls width (40-240 columns). The renderer tries vertical/compact layouts for narrow screens and fails clearly if it cannot show every connection; it never silently clips.

For all four Contract standards across Docker and Kubernetes, use task testing:demo:docker-kubernetes-four-contracts:present; see the mixed-runtime presenter walkthrough.

Press Enter to destroy owned resources and verify cleanup. Ctrl-C also cleans up and returns 130; SIGTERM returns 143. The default inspection limit is ten minutes (DOTX_POC_PRESENT_TIMEOUT, integer 1-1800 seconds). Timeout returns 124 and EOF returns 1, both after cleanup: neither is reported as a successful presentation. Headless launches are rejected before deployment, and DOTX_E2E_KEEP=1 is forbidden in presenter mode.

# Safe headless previews: print the real graph and render without deployment.
task testing:pocs:present:monitoring -- --dry-run
task testing:pocs:present:secure-api -- --dry-run
task testing:pocs:present:remediation -- --dry-run

The noninteractive testing:pocs:*:live tasks remain unpaused. Use the presenter tasks above, not the full failure-injection suite, in front of an audience. For preparation, task testing:pocs:present:controls exercises Enter, EOF, timeout and real signals with live Prometheus on overridden port 19041. task testing:pocs:present:rehearse requires clean commits, drives all three presenter flows through a real terminal, inspects live status during each pause, then verifies cleanup. It preserves checkout/CLI fingerprints and redacted results under ignored DOT-Testing/e2e/target/presenter/ and poc-rehearsals/. Keep those receipts and the exported PDF as an explicitly labelled fallback, not evidence that a new live exchange occurred during the talk.

Prerequisites and fixed inputs

Use Linux amd64, Docker, curl, jq and Git. Acceptance harnesses also require Bash, flock, Python 3 and Task; ShellCheck checks their regressions. PoC10 needs kubectl and a Ready local Docker-driver Minikube node with context minikube. PoC6 additionally needs Docker BuildKit and read access to the pinned private producer through Git/gh, or POC6_SOURCE_DIR at the exact revision below. Automatically acquired PoC6 source uses the private run directory’s filesystem, not shared /tmp, and is removed after the run. A caller-supplied source checkout remains untouched.

git submodule update --init --recursive
task cli:install
dotx version
git rev-parse HEAD
git -C DOT-CLI rev-parse HEAD
git -C DOT-Repository rev-parse HEAD
task testing:pocs:dry-run

To display just the graph without running the acceptance harness:

dotx compose topology \
  DOT-Repository/Compositions/keycloak-apisix-opa-sparql/composition.yaml \
  --locked --color always

Install from the pinned CLI checkout: released 0.2.4 predates repository-wide composition validation. Dry-runs must pass before deployment. The three paths contain respectively 1, 5 and 2 compatible wires. Inspect their exact Anchor IDs, selected deployments and materializers; COMPATIBLE is not a live result.

1. PoC4: Node Exporter to Prometheus

Node Exporter -- metrics scrape wire --> Prometheus -- query API --> presenter

Graph: DOT-Repository/Compositions/node-exporter-prometheus-monitoring/composition.yaml. Producer context: PoC4 c03eca71a9d87358603a1d89fa0eca58a9dabe03. Node Exporter provides metrics; Prometheus requires the scrape endpoint. A CONFIG_FILE materializer inserts ENDPOINT_HOST_PORT at /scrape_configs/0/static_configs/0/targets/0. Prometheus’s query Anchor uses its DOT-local Contract. OpenMetrics is not a fabricated OpenAPI operation.

dotx compose inspect DOT-Repository/Compositions/node-exporter-prometheus-monitoring/composition.yaml --locked --json
task testing:pocs:monitoring:live

The task waits for readiness, verifies the exact resolved scrape target is healthy, checks up{job="node-exporter"} equals 1, and verifies the exporter version through node_exporter_build_info. Expect PASS, then a receipt with exit=0, cleanup=PASSED. Override DOTX_POC4_QUERY_PORT if 19040 is busy.

This grants no host namespaces or host root filesystem mounts. It observes the exporter’s container, not the testbed host. Full log/dashboard flow, MITM detection and mitigation remain outside this slice.

2. PoC10: authenticated, policy-controlled SPARQL

Presentation preflight

After preparing the local cluster and rehearsing once to cache images, run this read-only gate before presenting. It is scoped to this secure-API composition, not the four-Contract fixture or all catalogue deployments:

# Keep these overrides in the same terminal for preflight and presentation.
export DOTX_POC10_NAMESPACE=dotx-poc10-presentation
export DOTX_POC10_FORWARD_PORT=19010
task testing:demo:preflight DEMO=secure-api
task testing:pocs:present:secure-api

The preflight requires local Go only to inspect the installed binary’s embedded build information. It requires clean CLI/catalogue checkouts and a binary built from the CLI’s exact revision, rather than trusting the 0.2.5 version label. If mismatched, review/commit CLI changes and run task cli:install. It prints the CLI SHA-256, Design/catalogue revisions, verifies local Contract assets through offline catalogue validation, and resolves the reviewed composition lock.

It then checks Docker/Compose access, the minikube context, one Ready Linux-amd64 node without resource pressure, an unused namespace and TCP port, and every selected manifest image in the Docker-driver Minikube cache. All five selected images are digest-pinned at their rehearsed versions; tags remain in the reference for readability. Preflight rejects tag-only references and cached images whose reported platform is not Linux amd64. It prints the resolved image IDs without dumping image configuration. This is cache availability, not a remote registry/Contract URL check, image vulnerability scan, or API acceptance. The check is bounded and does not start tools, pull images, create Secrets, deploy, adopt resources or clean anything up. Read-only CLI resolution can use temporary files/cache; no composition lifecycle state is written.

If a prerequisite fails, correct only that prerequisite and rerun. Prepare the cluster explicitly with dotx tool check kubernetes --start if needed. To warm images, run the existing task testing:pocs:secure-api:live acceptance task before the talk; it may download images and must finish with verified cleanup. For an occupied port choose another DOTX_POC10_FORWARD_PORT. Never delete a foreign namespace to make preflight pass: choose a new name, or recover only a previous run whose ownership is recorded in its receipt. Preflight is a point in time check, not a reservation; the live harness repeats ownership checks.

What the live result proves

The harness now seeds a known RDF triple into the disposable backend, then reads that stored value through the authenticated gateway. Acceptance requires exactly one expected literal, rather than a constant SELECT expression that would work with an empty database. An authenticated INSERT attempt must be rejected with 403. Seeding is explicit out-of-band test setup in the owned namespace; it is not a claim that the public read-only interface authorizes writes.

The same live task also requires a reversible authorization transition:

  1. Authenticated query of the seeded data: HTTP 200 and the expected literal.

  2. Temporarily deny reads in this run’s OPA module: the same authenticated query must complete with HTTP 403, not a redirect or transport failure.

  3. Restore the original module, read it back, then issue a fresh authenticated query: HTTP 200 with the same stored value.

The console prints these three stages. The redacted result.json contains policyTransition.httpStatuses: [200, 403, 200], restored: true and storedDataUnchanged: true only after every assertion succeeds. The inspection pause happens after restoration, so the displayed composition remains usable.

Policy administration is an explicit operator-side demonstration action using OPA’s Policy API, not a sixth Anchor wire, automatic remediation, or a production policy-management design. The harness requires ownership of the applied namespace and an exact match to the reviewed policy before mutation. A failed or ambiguous update triggers a restoration attempt; any failure still invokes the parent harness’s owned-resource cleanup. It never changes another namespace’s policy. In production, OPA recommends bundles for policy distribution; this local demonstration uses the API to make one bounded, observable transition.

Offstage dependency-outage qualification

task testing:pocs:secure-api:resilience:live

Run this separate preparation task offstage, not during the short task demo. It repeats a real OPA process outage twice, then injects a failure after OPA has stopped to verify restoration and cleanup. The existing canonical composition is reused; no duplicate DOT or deployment descriptor is introduced.

Each successful run verifies an authenticated stored-data query (HTTP 200), zero OPA pods and an authenticated rejection (403), then a new OPA pod and the same stored value (200). The pinned APISIX OPA plugin fails closed with 403 when its decision service is unavailable; a redirect, 5xx or transport failure does not pass. Pod-drain polling uses a 90-second deadline with individually bounded API requests; an in-flight request can extend the drain’s wall-clock duration. Rollout has a 180-second limit. This process outage is distinct from changing a Rego rule.

The operator-side control verifies the namespace UID, Deployment UID, exact pinned image, replica count and resource version before conditional patches. It attempts restoration after ambiguous responses or injected failure, never adopts a replacement Deployment, and leaves final ownership-safe teardown to the existing harness. Private per-run resilience-control.json, resilience-restoration.json and successful resilience.json receipts retain only redacted assertions. The aggregate receipt under DOT-Testing/e2e/target/poc-wave/ requires unchanged source/CLI fingerprints, two recoveries and verified failure cleanup.

This does not qualify Keycloak outage/token-cache behaviour, gateway failover, resource pressure, HA, durable backup/restore, stateful upgrades or the complete producer PoC. Those remain separate operational acceptance work.

Composition and ordinary live route

These arrows show logical PROVIDES-to-REQUIRES wires, not HTTP packet direction:

Keycloak -- discovery --> APISIX <-- SPARQL -- Oxigraph
OPA ----- decisions ---> APISIX -- protected capability --> Client
Keycloak ---------------- token -------------------------> Client

Graph: DOT-Repository/Compositions/keycloak-apisix-opa-sparql/composition.yaml. Producer context: PoC10 e6a755145bbb71551916163209c0be6e9e996f9c. Five instances exchange through five wires:

  • Keycloak discovery to APISIX;

  • Oxigraph SPARQL to APISIX;

  • OPA policy decisions to APISIX;

  • OAuth token endpoint to the client (TOKEN_URL);

  • protected SPARQL capability to the client (CAPABILITY_URL).

Native Secret references supply credentials. Routes/policy are explicit, composition-owned inputs, not automatic translation. OIDC/OAuth Contracts come from canonical bundles. SPARQL and the legacy OPA workflow remain explicit protocol interfaces, not invented official vendor OpenAPI documents.

kubectl config current-context
kubectl get nodes
dotx compose inspect \
  DOT-Repository/Compositions/keycloak-apisix-opa-sparql/composition.yaml \
  --locked --json
task testing:pocs:secure-api:live

Expect a fresh namespace and native test Secrets, HTTP 401 for missing and malformed bearer tokens, authenticated POST 403, and an authenticated GET returning mare-poc10 from the real SPARQL engine. Every required client input is checked. The harness destroys its namespace and forward; the receipt must say cleanup=PASSED. Override DOTX_POC10_FORWARD_PORT if 19010 is busy.

During the presenter pause, inspect the printed private-cache compose status command and result.json. The five compatible wires are composition/configuration evidence; the four HTTP assertions above are the live end-to-end evidence. They are not five independent native Contract probes or full response-schema validation. Press Enter to clean up and retain the receipt. Re-run from the cleaned state to check repeatability; never treat a previous receipt as a new live exchange.

The invalid token is fixed public test data; real access tokens are never printed. invalidBearerHttpStatus in result.json records the checked 401. The bounded check ignores local curl configuration and does not follow redirects. It proves rejection of this malformed token, not expiry/revocation handling, issuer/audience isolation, signing-key rotation, or a security certification.

Oxigraph substitutes for GraphDB; a synthetic machine client uses client credentials instead of a password grant. This does not accept the full producer GraphDB/LDAP/Data Security Service stack, telemetry/events or automated response. HTTP, bootstrap defaults and the read-only policy are demo settings, not production security hardening.

3. PoC6: explicitly adapted remediation rehearsal

CACAO interpreter [adapter] -- MQTT/OpenC2 via Mosquitto --> actuator
actuator -------------------- remediation call ---------> NWDAF [DOUBLE]

Graph: DOT-Testing/e2e/poc6-cacao-openc2/scenario.yaml, not a catalogue example. Producer revision: cd359b25df1b010324869d7e1c755067070e42dd.

task testing:e2e:poc6-cacao-openc2:dry-run
task testing:pocs:remediation:live

A guarded interpreter adapter resolves the CACAO external broker URI. The unchanged pinned actuator receives OpenC2 over real Mosquitto/MQTT through the AsyncAPI wire, then calls the OpenAPI remediation endpoint. The exact job UUID must reach the far end. That endpoint is an NWDAF double, not real NWDAF remediation. Telemetry, AI and playbook selection remain unaccepted. Override DOTX_POC6_INTERPRETER_PORT/DOTX_POC6_NWDAF_PORT if 18261/18262 are busy.

Repeatability, cleanup and recovery

task testing:pocs:rehearse

This runs each slice twice, followed by injected failure and real SIGINT/SIGTERM cleanup controls. It records the CLI hash, three checkout revisions, tracked/untracked fingerprints, runtime image identities and per-run receipts under DOT-Testing/e2e/target/. Changed inputs invalidate the aggregate receipt. Dirty-worktree evidence does not claim those changes were already published.

The manual Anchor live E2E workflow’s first-wave selection runs the same checks and rehearsal driver. Remote infrastructure and queue failures remain separate from local acceptance; no workflow success is claimed before it runs.

Harnesses refuse existing resources, lock fixed identities, use private caches and check owned leftovers. Anonymous Docker volumes are removed; unrelated resources are untouched. PoC6 test images remain cached. DOTX_E2E_KEEP=1 records SKIPPED cleanup and cannot pass acceptance.

Kubernetes namespace creation records the UID from its create response. Cleanup rejects unknown or replaced ownership and uses a server-side UID precondition for namespace deletion. Lost create confirmation is a failed cleanup requiring review, not permission to adopt a same-named namespace.

Current-source named Helm restart with explicit --forward also reconciles a previously recorded forward when its custom release name differs from the DOT product name. Replacement requires an exact namespace/service/port mapping in the private forward registry; unrelated namespaces, services, mappings and unrecorded listeners are not adopted. This is a Next runtime correction, not a change retroactively added to the published 0.3.0 CLI binary. Keep the rehearsed source/binary set together.

If cleanup fails, preserve the printed run directory. Set XDG_CACHE_HOME to its cache directory and, for Kubernetes runs, set KUBECONFIG to that run’s private kubeconfig. Do not follow a later global context change or share the saved kubeconfig. Stop if the original run files are missing; a new run’s state does not authorize recovery. Confirm the namespace still has its recorded UID; stop and review a mismatch or an unconfirmed identity. Inspect dotx compose status <composition>, then retry destroy on the same graph only while the original ownership still matches. Inspect only recorded namespaces and resolved identities. Never strip finalizers or delete unrelated workloads. Select an unused port instead of killing another service. Review missing Contracts, inputs or stale locks before intentionally regenerating a lock.

Full-catalogue appendix

DOT-Testing/interoperability/FIRST-WAVE.md and pocs.yaml retain all eleven PoCs and remaining gaps. DOT-Repository/CONTRACT-AUDIT.md separates official and source-derived Contracts, protocol-only interfaces and runtime-only brokers. Validation-only fixtures, stubs, adapters and doubles remain labelled. Declaration completeness is not runtime acceptance or production certification.
