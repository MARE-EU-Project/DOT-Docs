4. Grow the system with Grafana

Your reviewed two-tool draft describes Node Exporter and Prometheus. Extend the catalogue version of that graph with Grafana, adding one Vertex, one Edge and explicit browser forwarding. Review its declaration and lock, then start it and verify the full chain.

Continue in the same Bash shell with Lesson 3’s reviewed files. If you followed only the preview and never applied the graph, no destroy step is needed. If you started it, first complete its cleanup and verify resource absence. The new draft gets a fresh ownership UUID; it does not adopt another graph’s runtime resources.

Goal: a reviewed three-DOT, two-Edge graph, Grafana returning the Node Exporter scrape, and verified cleanup. You will learn: extending a graph, provisioning a datasource and supplying a password through a reference.

Prepare the next real tool

Download the Lesson 4 helper as commands.sh into your lab directory. Open it to review the setup, then run this from the Lesson 3 shell:

LAB="$LAB" DOT_REPOSITORY="$DOT_REPOSITORY" bash "$LAB/commands.sh" prepare

The helper validates the catalogue Grafana definition, prepares the provisioning files and creates dashboard.yaml with a fresh UUID. The graph uses the catalogue Prometheus definition that owns the Contract Grafana references. The query selects the catalogue job label job="node-exporter".

The Grafana service declares GF_SECURITY_ADMIN_PASSWORD as an optional sensitive setting. This lesson supplies it through a secret reference to initialize the admin password in a fresh Grafana database.

The datasource file is an instance input. uid: hero-prometheus makes it easy to select and test. access: proxy makes Grafana’s backend query Prometheus over the composition network; the browser does not need to reach an internal container address. The Edge replaces the .invalid URL before deployment.

This catalogue release also requires an Elasticsearch provisioning file. The empty, valid grafana-empty.yml deliberately provisions no Elasticsearch datasource: that integration is outside this lab. Do not draw a fictitious Edge or claim that it has been tested.

Extend the existing graph

Open $LAB/dashboard.yaml using the editor/save workflow:

nano "$LAB/dashboard.yaml"

Before editing, it has two DOTs and one Edge. You will add one item to each of two existing lists. Keep the earlier items, ownership UUID; do not paste another root vertices: or edges: key. Each snippet below is a list item, beginning with - name, at the same indentation as the existing items. Keep the four leading spaces shown before each - name in the CLI-created draft.

In the existing node-metrics-to-prometheus Channel, change the materializer’s source to prometheus.yml. This reuses the scrape configuration from the previous lesson, which is readable by the non-root Prometheus container.

Add Grafana under vertices

Append this after the existing prometheus instance:

    - name: grafana
      source: repository://Grafana@13.3.0
      dotId: Grafana@13.3.0
      dotVersion: 13.3.0
      deployment: docker
      dependsOn: [prometheus]
      deploymentInputs:
        environment:
          - name: GF_SECURITY_ADMIN_PASSWORD
            secretRef: {store: environment, name: HERO_GRAFANA_PASSWORD}
        configFiles:
          - source: grafana-empty.yml
            target: /etc/grafana/provisioning/datasources/elasticsearch.yml

Add the second connection under edges

Append this after the node-exporter-to-prometheus Edge:

    - name: prometheus-to-grafana
      from: prometheus
      to: grafana
      channels:
        - name: prometheus-to-grafana
          fromConnector: promql-query-api
          toConnector: promql-query-api
          materializer:
            type: CONFIG_FILE
            source: grafana-prometheus.yml
            valueFrom: ENDPOINT_URL
            target:
              instance: grafana
              service: grafana
              path: /etc/grafana/provisioning/datasources/prometheus.yml
              jsonPointer: /datasources/0/url

Grafana’s monitoring-dashboard Connector becomes available automatically when you add its Vertex. The apply command below selects grafana/monitoring-dashboard explicitly for local browser access; no separate exposure declaration is needed.

The new Edge connects the Prometheus and Grafana vertices. Its Channel links the provided PromQL operation to Grafana’s required operation. Its materializer writes the selected Prometheus base URL into /datasources/0/url. The two Edges have different jobs: the first configures scraping; the second configures querying.

Here /datasources/0/url selects url in the first datasource entry. It replaces the .invalid placeholder URL you created in grafana-prometheus.yml with this graph’s Prometheus base URL.

secretRef names a host environment variable; it contains no password. The executor resolves it at apply time. Do not paste a sensitive value into the composition. Docker environment delivery is still visible to an authorized Docker administrator; it is not a vault or native Kubernetes Secret.

(
set -euo pipefail
dotx compose validate "$LAB/dashboard.yaml" \
  --repository "$DOT_REPOSITORY"
dotx compose lock "$LAB/dashboard.yaml" --repository "$DOT_REPOSITORY"
dotx compose topology "$LAB/dashboard.yaml" \
  --repository "$DOT_REPOSITORY" --locked
printf 'Extended graph verified: three DOTs, two Edges.\n'
printf '%s\n' \
  'Declaration review complete.' \
  'Next: supply a lab password, then preview and apply.' \
  'Complete the query and native cleanup checks before leaving the lab.'
)

Expected: three DOTs, two Edges. Open $LAB/dashboard.lock.json and use Lesson 3’s lock-field checklist. Keep the catalogue Prometheus and Node Exporter selections. The additional vertices[] entry must have instance: "grafana", source: "repository://Grafana@13.3.0", dotId: "Grafana@13.3.0", deploymentId: "docker" and a definition digest. The inputs[] now also pin grafana-prometheus.yml and grafana-empty.yml. Creating or inspecting the lock does not require the password; never paste a secret value into it.

Preview checkpoint

The declaration exercise is complete when validation and lock review succeed and topology shows three DOTs and two Edges with the inputs listed above. No composition has started yet. Continue below to supply the password, launch the graph and verify its query. If you choose only declaration review, keep these files and continue to Lesson 5’s extension choices; that route does not establish a working dashboard.

Set a password and start the extended system

Use a new lab-only password. The prompt does not echo it or put it in shell history. Keep this environment and the same binary for the lifecycle:

if read -r -s -p 'Choose a lab-only Grafana admin password: ' \
  HERO_GRAFANA_PASSWORD &&
  test -n "$HERO_GRAFANA_PASSWORD"; then
  printf '\n'
  export HERO_GRAFANA_PASSWORD
else
  unset HERO_GRAFANA_PASSWORD
  printf '\nNo password set. Repeat this prompt before applying.\n' >&2
  false
fi

Ports 19041 and 13000 must be free. Use only the isolated development host and network described at the start. Keep the cleanup command below available before applying; use it after a failure as well. The next block previews both forwarding selections first; a failed preview prevents its apply command from running. Runtime preflight, including the dry-run, needs the referenced password available.

export LAB DOT_REPOSITORY DOTX_TUTORIAL_DOCKER_ID TUTORIAL_PORT DASHBOARD_PORT
bash "$LAB/commands.sh" start

Verify the whole chain

Grafana health is the first check. The datasource query is the second: it exercises the connection to Prometheus and the Node Exporter scrape from Node Exporter. Complete both before calling the chain successful.

Run the health check and datasource query together:

bash "$LAB/commands.sh" verify

Expect Ready: Grafana 13.3.0 followed by Verified: Grafana queried the Node Exporter scrape (value 1).

For a browser on another machine, follow the SSH forwarding instructions for the selected dashboard port. Open Grafana, sign in as admin with your chosen password, and open Explore. Choose the provisioned Prometheus datasource and run:

up{job="node-exporter"}

Expect a sample with value 1. Grafana UI labels can vary by release; the helper provides a reproducible check. You have extended one running use case without putting a use-case-specific datasource or password into the shared product definitions.

Clean up the complete graph

if test -n "${DOTX_TUTORIAL_DOCKER_ID:-}" &&
  current_docker_id="$(docker info --format '{{.ID}}')" &&
  test -n "$current_docker_id" &&
  test "$current_docker_id" = "$DOTX_TUTORIAL_DOCKER_ID"; then
  dotx compose destroy "$LAB/dashboard.yaml" \
    --repository "$DOT_REPOSITORY" &&
  unset HERO_GRAFANA_PASSWORD &&
  {
    if test -f "$LAB/grafana.curl"; then
      rm -- "$LAB/grafana.curl"
    fi
  } &&
  printf 'Destroy succeeded: keep the workspace files for reference.\n'
else
  printf '%s\n' \
    'Docker target is missing, changed or unreachable.' \
    'Restore the original Docker connection.' \
    'Do not replace its recorded ID.' >&2
  false
fi

Expected: all three owned instances stop. This is disposable storage; downloaded images remain cached. Keep your authored files as a learning reference, but retain the original cache and lock if cleanup did not finish. Do not remove unrelated resources or change a lock to adopt an existing instance. Require Cleanup verified: from the native Docker audit. The final message and password removal happen only after destroy succeeds. Removing a password or seeing a missing lifecycle record does not establish resource absence. Keep the original binary, draft, lock and cache while cleanup is unverified; restore Docker access and retry that same destroy command. If it fails, retain the current environment and use the recovery steps before retrying.

Checkpoint

Complete this lesson when Grafana returns the Node Exporter sample and Cleanup verified: confirms absence of the owned resources. Retain the draft, lock and inputs for reference. The declaration checkpoint alone does not establish a working dashboard.

Explain it back: what stays reusable when you add a dashboard?

Prometheus keeps its product identity, Contract and Connectors. Grafana’s datasource, the selected Prometheus instance, the password reference and both Edges belong to this composition. The catalogue Grafana definition declares the password setting. The composition supplies its secret reference, and the executor resolves the value when starting the service.
